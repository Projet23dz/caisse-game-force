1. **Tailscale منفصل عن البرنامج**
   - حُذف Tailscale المدمج من: برنامج Windows، تطبيق الهاتف، مثبّت السيرفر، CI.
   - عند تحديث السيرفر تُزال المهمة القديمة «CashPro Tailscale» تلقائياً.

2. **أنواع عمليات جديدة** (المدير فقط): الإعدادات ← أنواع العمليات ← «نوع عملية جديد» (اسم + ⬆ دخول / ⬇ خروج + لون)، ثم فئاته في صفحة النشاط ← الإعدادات ← الفئات.
3. **نشاط الموظفين 👁** (المدير): كل إضافة/تعديل/إلغاء قام به غيرك مع القيمة قبل/بعد، «تمّت المراجعة»، «مراجعة الكل»؛ الإعدادات: كل شيء / التعديلات والإلغاءات فقط / ابتداءً من مبلغ.

## 4. نقل المستودع إلى حساب آخر (خطوة بخطوة)

### 4.1 النقل
1. حساب `projet23dz-max` ← المستودع `cash-gameforce` ← **Settings** ← أسفل الصفحة **Danger Zone** ← **Transfer ownership**.
2. اكتب اسم الحساب الجديد واسم المستودع للتأكيد ← Transfer.
3. صاحب الحساب الجديد يقبل النقل من الرسالة التي تصله على البريد (خلال يوم).
4. صاحب الحساب الجديد ← المستودع ← Settings ← **Collaborators** ← Add people ← `projet23dz-max` بصلاحية **Write** (أو Admin).
   - مهم: حساب GitHub المربوط بـ Claude يجب أن يكون صاحب المستودع أو Collaborator، وإلا لن تستطيع المحادثة الجديدة الوصول إليه.

ما ينتقل تلقائياً: الكود وكل تاريخه، الإصدارات (Releases) وملفات التثبيت، الروابط القديمة تُحوَّل (redirect) إلى الجديدة.

### 4.2 الأسرار (Secrets) — يجب إعادة إدخالها في الحساب الجديد
المستودع الجديد ← Settings ← Secrets and variables ← Actions ← **New repository secret**:

| الاسم | ما هو | من أين |
|---|---|---|
| `CASHPRO_SIGNING_PASSPHRASE` | كلمة سرّ مفتاح توقيع تطبيق أندرويد (المفتاح نفسه مشفّر داخل المستودع: `android-app/signing/`) | نفس القيمة التي أُدخلت سابقاً — **بدونها لن يُنشر APK**، وبمفتاح آخر لن يقبل الهاتف التحديث |

لا تُكتب قيم الأسرار في أي ملف أو محادثة.

### 4.3 الدقائق والدفع في الحساب الجديد
- المستودع خاص: الحساب المجاني يعطي 2000 دقيقة/شهر؛ دقائق Windows تُحسب ×2.
- منذ 2026-11-25: عند كل رفع للكود تُشغَّل **اختبارات Linux فقط**. البناء الثقيل (مثبّت Windows، APK) يُشغَّل يدوياً:
  Actions ← **CashPro — tests** ← **Run workflow** ← main ← (✓ release لنشر نسخة).
- يُنصح بوضع حدّ إنفاق صغير (Settings ← Billing ← Spending limit) وبطاقة دفع صالحة.

### 4.4 التحديث التلقائي على PALM01 بعد النقل
1. صاحب المستودع الجديد (أو Collaborator) ينشئ **مفتاح قراءة** (Fine-grained token): GitHub ← Settings ← Developer settings ← Fine-grained tokens ← Generate:
   - Resource owner: **الحساب الجديد** (صاحب المستودع)
   - Repository access: Only select repositories ← `cash-gameforce`
   - Permissions ← Repository ← **Contents: Read-only** (ولا شيء غيرها)
2. في CashPro (بحساب admin) ← الإعدادات ← **التحديثات** ← مصدر التحديثات:
   - المستودع: `اسم-الحساب-الجديد/cash-gameforce`
   - المفتاح: المفتاح الجديد ← حفظ ← «البحث عن تحديث».
3. المفتاح يُحفظ في السيرفر فقط (`C:\CashPro\config\update.json`) ولا يُرسل للأجهزة.

## 6. معلومات تقنية للمطوّر / للمحادثة الجديدة

### 6.1 البنية
- `database/` — PostgreSQL 15/16، كل القواعد المالية والصلاحيات داخل القاعدة (RLS + triggers). الملفات `01`–`06` للتثبيت الأول؛ **`07` وما بعدها تُعاد في كل تحديث** (يجب أن تبقى قابلة لإعادة التشغيل). آخر ملف: `10_types.sql` (أنواع العمليات + التنبيهات، رموز الأخطاء CP100–CP104).
- `api/` — Node 22 / Express 5 / zod 4 / pg / TypeScript. التوثيق: `api/API.md`.
- `client/` — واجهة TypeScript بدون مكتبات، تُبنى بـ `npm run build` في `api/`.
- `desktop/` — Electron: برنامج الحواسيب + مثبّت السيرفر (`desktop/server/setup-server.ps1`، `run-update.ps1`).
- `android-app/` — تطبيق WebView (لا Tailscale مدمج منذ 1.2.0).
- `.github/workflows/ci.yml` — الاختبارات والبناء والنشر (`.github/release-upload.sh` يعيد المحاولة عند أعطال GitHub ويُخرج الإصدار من وضع المسودة).

### 6.2 الاختبارات (قبل كل commit)
```bash
# قاعدة البيانات (62/62)

```
